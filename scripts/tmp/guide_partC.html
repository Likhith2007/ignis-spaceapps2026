09 · Downloads
Date-range search & downloadable products

The brief's "region + date range → fire history" flow ships as RangeSearch: from/to date inputs (iOS-safe 16 px font) with 7 / 14 / 30 / 45-day presets. A search runs spans of up to 45 days as 10-day FIRMS chunks through the unified pipeline, dedupes overlapping detections, and computes per-day, per-sensor and total analytics from authoritative counts — capped at 20,000 rows with an explicit truncation flag so the accounting is always honest.

Clickable per-day bars jump the map to that day. Three exports — exactly what the brief asks for — work for any AOI, curated, searched or hand-drawn: the detections CSV (per-detection rows with sensor, time, FRP, confidence, coordinates and ML class), the daily-counts CSV (per-day/per-sensor table), and GeoJSON point geometry for GIS import. Empty and too-long states are designed, and results disclose when they come from the archive rather than near-real-time.

Every model repository ships the exact training script, the data snapshot, metrics including baselines and limitations, and a full model card — the same open-science standard as NASA+IBM's Prithvi releases.

11 · Operations
Status rail & automation

The bottom rail verifies all upstream systems live on every load: FIRMS, api.nasa.gov, GIBS, EONET, the Hugging Face endpoint, Open-Meteo, and the Earthdata JWT — including the days remaining until token expiry, so a credential sunset is visible before it can break a demo. /api/health runs the same checks server-side. In the 2026-10-29 production audit, 15/15 API endpoints returned 200 with real data; the two 400s observed were parameter-validation tests, confirmed 200 with proper arguments.

Automation: GET /api/hooks/digest returns a machine-readable daily fire digest for n8n, GitHub Actions or Vercel Cron, with an optional bearer-token guard. An importable n8n workflow ships in the repository (automation/ignis-n8n-workflow.json), the cron schedule is wired in vercel.json, and the operations runbook documents the deployment path end to end.

"How do I…?" — quick recipes

  • "Is this region abnormal right now?" → TopBrief (alert banner) → Calendar tab → "this month vs historical median" KPI → Time-Series anomaly rings.
  • "What is that single fire on the map?" → click the dot → AI event card → "Ask the Analyst about this fire".
  • "Get last month's detections for my province." → ⌖ draw the box → RangeSearch → set dates → download detections CSV / GeoJSON.
  • "Is fire activity trending up over 26 years?" → Science Lab → Trend significance (Mann-Kendall + Sen's slope) → Memory & persistence (Hurst) → Extremes (return periods).
  • "Do MODIS and VIIRS agree here?" → Dynamics scatter (1:1 line) → Science Lab → Sensor agreement (Bland-Altman ratio + LoA) → SensorPanel live ratio.
  • "Warn me about fires near my farm." → Watchlist tab → save the place + radius → keep the tab open (5-min recheck) or enable browser / e-mail channels.
  • "What kind of fire regime is this?" → Burn Regime tab → prototype badge + distance.
  • "Show me the 3D energy structure." → map 🧊 Fire Field or ⛰ Terrain towers → HUD rollup.

Accessibility and responsiveness are part of the feature set, not an afterthought: colorblind-safe calendar ramps, aria-pressed / aria-label on controls, listbox semantics, a keyboard-navigable 6-step guided tour (◈ header button, re-runnable, remembered in localStorage), ≥ 40 px touch targets, fluid map heights on mobile, popup clamps with inner scroll, safe-area insets — verified with zero console errors and zero horizontal overflow at 1440×900 and iPhone 390×844.

How the claims in this guide were verified

Verification record

Every quantitative claim above traces to a runnable check, not a narrative. The science layer is guarded by 28/28 synthetic ground-truth tests that plant a known signal — a planted trend for Mann-Kendall, an AR(1) series for the ACF, a 24-month cycle for the periodogram, a 3× proportional ratio for Bland-Altman, a gradient field for Moran's I — and assert each method recovers it. The harmonized record is rebuilt reproducibly by the pipeline scripts from the GIBS archive, so the calendar, regime prototypes and emissions estimates can be regenerated and audited by anyone.

On the operational side, the 2026-10-29 production audit verified 15/15 API endpoints returning 200 with real FIRMS/GIBS/EONET/GDACS data, ran headless-browser sweeps at 1440×900 and 390×844 with zero console errors, zero page errors and zero horizontal overflow, and exercised the guided tour, date-range search (46,480 detections in one 30-day query), the 26-year calendar and all seven Science Lab sub-tabs against live data.
